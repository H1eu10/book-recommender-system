# Структура приложения и API

Приложение сохраняет архитектуру React + Vite + TypeScript, FastAPI и данные JSON.

Никакие фреймворки пользовательского интерфейса, базы данных или внешние сервисы не добавлены.

# Фронтенд

- `App.tsx`: загружает библиотеку, переключает режимы рекомендаций, выполняет поиск/фильтрацию/пагинацию и управляет открытой в данный момент книгой.

Сохраняется макет панели инструментов, панель рекомендаций и сетка.

- `RecommendationPanel.tsx`: форма настроек TF-IDF и результатов.

- `PersonalizedPanel.tsx`: загружает список профилей/моделей, отображает историю и персонализированные результаты.

Запросы отменяются при смене профиля или выходе из режима.

- `BookCard.tsx`: общая карточка книги, оценки и локализованные пояснения.

- `BookDetails.tsx`: нативное диалоговое окно с поддержкой клавиатуры, нативных метаданных и похожих книг.

- `services/api.ts`: получает JSON и классифицирует ошибки перевода в интерфейсе.

- `locales/{en,vi,ru}.json`: метки, сообщения, общие темы и пояснения.

- `utils/localizeBook.ts`: выбирает подходящий перевод, возвращается к оригиналу, если перевод пуст

или содержит очевидные ошибки повторения символов/форматирования. Не изменяет набор данных.

## Бэкенд

- `main.py`: маршрутизация API и предоставление ресурсов для сборки Vite, если существует `frontend/dist`.

- `schemas.py`: проверка входных данных, схема книги, пояснения и два типа оценок.

- `book_service.py`: чтение и проверка JSON-каталога.

- `personalized_service.py`: адаптер приложения для существующих алгоритмов; кэши

базовая/контрольная точка, считывает профили моделирования, классифицирует все известные книги и обрабатывает ошибки.

- Модули алгоритма и экспериментальные скрипты сохранены в этой интеграции интерфейса.

См. документацию по алгоритму для обучения/валидации/тестирования.

## Конечные точки

| Метод | Конечная точка | Функция |

| --- | --- | --- |

| GET | `/api/health` | Статус сервера |

| GET | `/api/books` | Каталог и переводы |

| POST | `/api/recommendations/smart` | Рекомендации по предпочтениям |

| POST | `/api/recommendations/similar` | До 30 похожих книг; для пользовательского интерфейса требуется 5 |

| GET | `/api/profiles` | ID и количество понравившихся книг профиля моделирования |

| GET | `/api/profiles/{user_id}` | ID понравившейся книги и синтетический флаг |

| GET | `/api/models` | Статус доступности четырех моделей |

| POST | `/api/recommendations/personalized` | Предложения из выбранных профилей и моделей |

`POST /api/recommendations` сохранен как псевдоним `/smart` для совместимости с устаревшими клиентами.

`/docs` предоставляет полноценный OpenAPI на основе схемы. Некорректные данные возвращают 422; несуществующие книги/профили возвращают 404; недоступные данные или модели возвращают 503.

API настроек сохраняет ограниченные значения 0–1 для `score` и устаревшие поля `reasons`. Поля `explanations` добавляют код и структурированные значения для интерпретации пояснений клиентом.

API персонализации использует отдельный ответ с `score_type: ranking`; исходная оценка может быть отрицательной или больше 1 и не принудительно включается в схему оценки сходства.

## Потоки данных

Выберите предпочтения → `/smart` → каталог + TF-IDF → книга/оценка/объяснение → тег книги.

Выберите профиль → загрузите историю → выберите модель → `/personalized` → загрузите/кэшируйте подготовленную модель
→ известный тип книги → верните исходную оценку → тег книги.

Просмотрите подробности → прочитайте существующие метаданные → нажмите «Найти похожие» → `/similar` → список
связанных книг. В этих потоках не ведется запись данных и обучение.
